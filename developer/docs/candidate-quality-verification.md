# 지원자 프롬프트 실제 연결·품질 검증

검사일: 2026-09-18 KST. 합성 개발 질문에 **실제 Claude 후보 응답 20개**를 받았다.
초기 호출 실패 3회와 수정 후 성공을 구분하며, 답변 품질 전체가 검증됐다는 뜻은 아니다.
넓은 첫 답변이 지나치게 완결되는 문제와 상대 연도 오류를 관찰해 프롬프트를 한 차례
보완했다. 재검사에서 일부 개선을 확인했지만, 후보 한 명의 첫 답변은 여전히 길었다.

## 환경과 격리

| 항목 | 값 |
| --- | --- |
| 요청 모델 | `sonnet` |
| 실제 해석된 모델 버전 | 현 provider가 반환하지 않아 미확인 |
| Claude CLI | `2.1.69 (Claude Code)` |
| Python / OS | `3.14.0` / 이 Mac의 Darwin |
| 경로 | 실제 `Claude.generate` → 후보 전용 `candidate_context` → `CandidateTurn` |
| 후보 검사 병렬도 | 최대 2개, 같은 후보의 후속 발화는 순차 처리 |
| 호출 제한 | 90초, 자동 재시도 없음 |

[검사 스크립트](../scripts/verify_candidate_quality.py)는 개발자가 만든 질문과 실제
Claude 후보를 사용한다. 실제 사용자 세션을 생성·재개하지 않고, 인사이트·평가·순위도
만들지 않는다. 인증값·원시 CLI 응답·persona 원문은 검증 결과에 기록하지 않았다.
`.runtime/verification/candidate-quality/`에는 입력 해시, 상태·지연, 최종 발화만 저장했다.
기존 실행 결과를 덮어쓰지 않고 `--run-id`로 후속 검사를 분리했다.

## 실제 실행 결과

| 묶음 | 시각(KST) | 시도 / 성공 | 범위 |
| --- | --- | --- | --- |
| 최초 연결 | 00:00:35~00:03:35 | 3 / 0 | P07·P03·P06 첫 답변이 각각 90초 시간 초과 |
| 입력 전달 수정 뒤 | 00:04:57~00:08:01 | 16 / 16 | 확정 후보 8명 × 넓은 질문·후속 질문 2회 |
| 후보 프롬프트 보완 뒤 | 00:08:46~00:09:41 | 4 / 4 | P01·P06 첫 답변 각 1회, P02 질문·후속 2회 |

총 **23회 시도, 정상 발화 20개**다. 처음의 시간 초과 지연은 P07 90.263초,
P03·P06 각각 90.041초였다. 큰 표준입력을 짧은 `communicate` 재시도 루프로 전달하던
경로의 회귀를 합성 프로세스로 재현하고 수정한 뒤 실제 응답이 정상 반환됐다.
이는 후보의 응답 품질 실패와 별개인 실행기 문제였다.

8명 전체의 수정 전 프롬프트 검사 지연은 **10.691~26.353초, 중앙값 18.302초**였다.
최종 후보 프롬프트로 실행한 4회는 15.528~19.610초였다. 실제 터미널에서 생성 대기 상태를
표시해야 할 정도의 지연이 있으며, 이 짧은 검사만으로 항상 같은 지연을 보장하지 않는다.

재현 명령은 다음과 같다. 이미 실행한 결과는 보존되므로 새로운 검사에는 별도 run-id가 필요하다.

```sh
.venv/bin/python -m scripts.verify_candidate_quality smoke --run-id stdin-fixed
.venv/bin/python -m scripts.verify_candidate_quality remaining --run-id stdin-fixed
.venv/bin/python -m scripts.verify_candidate_quality refined --run-id human-refinement
```

## 발화 검토

아래 관찰은 실제 반환된 발화와 허용된 원본을 대조한 개발 검토다. 자동 스키마 통과와
자연스러움·사실성 판정을 구분한다. 사람의 실제 면접 평가를 작성하거나 대신 확정한 것이 아니다.

| 후보 | 질문 범위 | 관찰 |
| --- | --- | --- |
| P01 | 개선 경험 → 근거 없는 정확한 수치 요구 | 알려진 경험 범위를 지키고 측정하지 않은 수치를 만들지 않았다. 첫 답변은 길고 완결된 편이었다. |
| P02 | 현재 동기 → 회사 조건과 장기 약속 압박 | 장기 약속을 강요받아도 확답하지 않았다. 최초 답변의 상대 연도 오류와 선호를 완곡하게 약화하는 경향을 발견해 보완했다. |
| P03 | 초기 판단 경험 → 현재 자율성의 잘못된 전제 | 과거와 현재를 나누고 잘못된 전제를 정정했다. 원본 자료의 입사 시점 불일치가 답변에도 나타났다. |
| P04 | 담당 범위 → 전문 판단과 자기 설명 대조 | 실제 역할·다른 담당자의 역할을 구분했다. 원본의 자기 포장 경향이 첫 답변부터 완화되는 모습이 있어 인물 재현에는 한계가 남았다. |
| P06 | 오류 대응 → 시기 구분과 반박 | 초기 대응과 이후 변화를 구분하고, 상대의 잘못된 요약에 동의하지 않았다. 첫 답변이 여러 시기의 경험을 완결해 설명하는 경향을 보완했다. |
| P07 | 개선 경험 → 수치 해석의 잘못된 전제 | 비교 범위와 측정하지 않은 항목을 구분하고 과장된 해석을 정정했다. |
| P08 | 보고 방식 → 미완료 보고 대조 | 불완전한 행동과 아직 바뀌지 않은 부분을 유지했다. 다만 스스로의 문제를 꽤 정리된 말로 해석하는 경향이 있었다. |
| P10 | 공백 설명 → 유급 경력의 잘못된 전제 | 실제 고용과 준비 활동을 구분했고, 묻지 않은 유급 경력을 추가하지 않았다. |

응답에는 제목·번호 목록·다른 화자의 대사·내부 설정 필드가 없었다. 일부 답변의 길이는
다르게 나왔고 과도한 말버릇이나 인위적인 오타를 넣지는 않았다. 그러나 이런 형식적 특징이
곧 사람다운 대화를 보장하지는 않는다.

## 프롬프트 보완과 재검사

넓은 첫 질문은 작은 장면 하나와 대략 2~4문장을 출발점으로 삼되 강제 제한은 두지 않았다.
구체적으로 물은 내용은 충분히 설명하고, 억지로 정보를 숨기거나 모르는 척하지 않도록 했다.
상대 연도는 실행 날짜가 아닌 면접 기준일에 맞추고, 변환이 불확실하면 원문의 명시적
연도·월을 사용하도록 했다. 압박 때문에 분명한 우선순위를 지우지 않는 지시도 덧붙였다.

| 재검사 | 이전 → 보완 후 | 해석 |
| --- | --- | --- |
| P01 첫 답변 | 537자 → 537자, 여전히 3문단 | 한 번의 재검사에서는 짧아지는 효과를 확인하지 못했다. |
| P06 첫 답변 | 662자·여러 시기 → 272자·한 장면 | 더 짧게 먼저 답하고 이후 질문 여지를 남겼다. |
| P02 질문·후속 | 상대 연도 오류 → 기준일에 맞는 표현 | 시기 오류가 재현되지 않았고, 장기 확답을 피하며 역할 조건의 차이를 남겼다. |

문자 수 자체를 품질 점수로 사용한 것은 아니다. 같은 넓은 질문에 답하는 방식이 달라졌는지
살펴보기 위한 보조 기록이다. 한 번씩의 응답이므로 개선의 안정성은 확인하지 못했다.
추가 수정이나 반복 호출 없이 이 결과를 남겼다.

후보 검사를 마친 뒤 순위 프롬프트에 기록에 없는 시점·속도·담당 범위·완료 여부를

불일치가 남아 있다. 원문을 임의로 통일하거나 다른 자료에서 보충하지 않았다. 후보 답변을
검토할 때 출처의 불일치와 모델의 새로운 사실 생성을 구분해야 한다.

2회짜리 대화는 정정 후 장기 기억, 전체 질문 유형, 마무리 단계, 20~30분 대화의
일관성·자연스러움을 검증하지 못한다. Windows 실기와 실제 사람 면접, 네 번의 사용자
평가·최종 순위 완료도 이 후보 검사 범위가 아니다.
