# 터미널 면접 구현·검증 계획

기준일: 2026-09-18. 실행 계약은 [스펙](terminal-interview-spec.md), 실제 수행 결과는
[검증 기록](verification.md)에 둔다. 초기 전환은 구현됐으며 현재 구조의 변경·검증 순서를 정리한다.

## 현재 구조

| 책임 | 구현 위치 |
| --- | --- |
| 한 번 배정·확정 후보군 | `harness/allocation.py`, `candidate_pools.json` |
| 상태·잠금·원문·확정 사본 | `harness/storage.py`, `models.py` |
| 역할 입력·후보 자료 | `harness/candidate.py`, `harness/resources/candidate_runtime/` |
| 인증·모델 실행·취소 | `harness/auth.py`, `provider.py` |
| 시간·차례·마무리 | `harness/interview.py` |
| 터미널·시작·사용자 확인 | `harness/terminal.py`, `onboarding.py`, `__main__.py` |
| 로컬 최종 순위 | `harness/finalize.py`, `harness/resources/prompts/ranker.md` |

사용자 진입점은 설치 후 `python -m harness start`다. 준비된 환경에서는 기준 작성·확인을 진행한다.
자동 설치와 OS별 실행 파일, 시작 시 개발 테스트 실행은 제품 흐름에 포함하지 않는다.
모델 실행에 필요한 인증 확인과 자료 검증, 사용자 시작·평가 확인은 유지한다.

## 변경 순서와 완료 조건

1. 변경할 계약과 재현 조건을 정한다. 기존 실패를 고치는 작업은 의미 있는 회귀 검사를 먼저
   작성하고 실패를 확인한다. 문서 정리처럼 동작이 바뀌지 않는 작업에는 구현을 복제하는 테스트를 추가하지 않는다.
2. 자료·역할 경계를 유지하며 해당 책임의 코드만 변경한다. 후보 자료를 다시 가져올 때는
   허용된 과거·현재 파일만 읽고 기존 사실과 불확실성을 보존한다.
3. 관련 검사를 통과시킨 뒤 전체 자동 검사와 정적 검사를 실행한다. 실제 모델 호출이 필요한
   변경은 별도 개발 입력으로 적은 수의 목표 사례부터 확인한다.
4. 설치본에서 자료·프롬프트가 로드되는지 확인하고 README·스펙·검증 기록을 현재 동작에 맞춘다.
   세션·인증값·개발용 실제 호출 기록은 공유 패키지에 넣지 않는다.

개발 환경의 공통 검사:

```sh
python -m pip install -c requirements.lock.txt -e '.[test]'
python -m pytest -q
python -m harness doctor
```

## 반드시 보존할 회귀 범위

- 배정: P07 선행, 나머지 세 구간 각 한 명, 고정 순서, 후보 자료 완비, 재추첨 없음.
- 역할: 중첩 입력 허용 목록, 지원자에게 기준·평가 차단, 면접관·순위 모델에 후보 설정 차단.
- 시간·차례: 1,800/1,200초 고정 마감, 마무리 전환, 중단·재개·시계 후퇴, 늦은 응답 폐기.
- 기록: 단일 작성자, 발화 한 번 확정, 출력 중단 복구, 외부 편집·잘림 감지, 명시적 복원.
- 사용자 판단: 시작 기준 확인, 빈 평가와 변경 여부 불일치 차단, 네 번째 평가 전 순위 생성 금지.
- 순위: 실제 원문 인용, 후보별 근거 분리, 최종 기준 해시, 확정 결과 재사용.
- 실행기·터미널: 큰 입력, 취소·타임아웃·자식 프로세스 정리, 한국어 입력과 대기 상태의 공존.

## 실제 연결과 품질 검증

자동 테스트·`doctor`·실제 Claude·OS 실기는 구분한다. 합성 평가를 실제 사용자 평가처럼 기록하지 않는다.
사용자 면접에서는 실제 입력을 기다리며 검사 편의를 위해 단계를 건너뛰지 않는다.

후보 프롬프트 검사는 넓은 질문→구체적인 후속 질문, 모르는 수치, 잘못된 전제, 압박 후 선호 유지,
긴 대화의 사실 일관성을 확인한다. 말투의 유창함이나 글자 수만으로 품질을 판단하지 않는다.
후보 설정을 대조하는 품질 검토는 면접관·순위 모델 입력과 분리한다.

실제 호출 기록에는 날짜·모델 별칭·CLI 버전·자료/프롬프트 해시·시도 수·지연·오류를 남긴다.
인증값과 후보 설정 원문은 출력하지 않는다. 실패한 짧은 사례를 무한 재시도하지 않으며,
질문이나 프롬프트가 바뀐 검사 결과는 앞선 실행과 구분한다.

현재 후속 과제는 긴 기록의 순위 생성 시간 초과, 면접관과 하네스의 마무리 질문 중복,
후보가 새로운 사건·결함을 보충하는 문제다. 이 문서의 정리가 해당 문제를 고쳤다는 뜻은 아니다.
별도 복사본의 인간화 v2 실험은 현재 원본에 반영하지 않았다.
