## 3. 단계별 작업

### P0. 기준과 호환성 정리

기존 테스트 결과와 `doctor` 출력을 먼저 기록한다. 실제 모델이나 운영 서버를 호출하는 시작 명령은 실행하지 않는다. 코드에서 카카오·운영 서버·구 세션 형식 의존성을 조사하고 제거 목록을 만든다.

`AGENTS.md`와 `CLAUDE.md`를 새 스펙에 맞춰 갱신한다. 후보 과거·현재 자료의 제한적 사용은 허용하되 미래 결과·운영 상태·자격 증명의 반입 금지는 유지한다. 카카오 조작과 제출 의무를 없애고 실제 사용자 판단 대기 규칙을 남긴다.

`founder-terminal-1`과 `.runtime/terminal-light`를 신규 기본값으로 정한다. 구 세션을 감지하면 보존하고 새 경로로 안내하는 동작을 먼저 정한다. 구 세션의 JSON을 직접 수정하거나 카카오 관찰 기록을 로컬 확정 발화로 변환하지 않는다.

완료 기준: 유지/제거 범위와 새 세션 경계가 코드·실행 규칙에서 일치하며, 기존 세션 파일에 쓰기가 발생하지 않는다. 대응 기준: A10.

### P1. 후보 자료 추출과 검토

참고 원본의 candidate-actor 계약·프롬프트·스키마를 반영하되 서버 실행기와 전체 `AuthoredWorld`를 가져오지 않는다. 기존 프로젝트의 Claude 실행기를 사용한다.

확정 후보군 8명 각각에 대해 다음 작업을 수행한다.

1. `history.json`, `motivations.md`, `behavior_patterns.md`, `traits.md`, `self_expression.json`, `current_state.json`을 읽고 과거·현재 범위와 공개 지원 자료의 일치 여부를 검토한다.
2. 스펙 5절의 필드만 추출한다. 현재 상태의 확실성은 보존하고 `future_relevance`·근거 ID·내부 평가 메타데이터는 제거한다.
3. 글 안에 남은 내부 참조가 있으면 참조 표시와 후보가 아는 사실을 구분한다. 모르는 참조를 미래 자료에서 찾아 보충하거나 모델로 재창작하지 않는다. 해결되지 않으면 해당 자료 검토를 완료 처리하지 않는다.
4. 결과를 후보 역할 전용 패키지에 저장한다. 일반 공개 자료 로더가 자동으로 합치지 않도록 경로와 API를 분리한다.
5. 원본 상대 경로와 해시, 추출 버전, 결과 해시를 기록한다. 사용자 이름이 포함된 개발 머신 절대 경로를 런타임 의존성으로 만들지 않는다.

후보의 수치·말투·성향을 무작위로 바꾸지 않는다. `미래`나 `퇴사` 같은 단어만으로 문장을 삭제하지 않는다. 현재의 장래 희망과 확정된 미래 결과는 의미가 다르므로 허용 목록과 원문 검토를 함께 사용한다.

완료 기준: 8명분 모두 검증되고 추첨 후보군이 유지된다. 허용된 파일만 읽었으며, 만들어진 persona에 시나리오·근속 수치·구간·비밀 인증값이 없다. 대응 기준: A02, A07.

### P2. 상태와 발화 확정

`Config`, `Session.create`, `allocate`, 상태 표시에서 서버·방·발신자 필수 설정을 제거한다. 세션 생성은 모델 기본값과 로컬 자료만으로 가능하게 한다.

면접마다 현재 차례, 요청 ID, 직전 메시지 ID, 역할, 입력 해시, 시도 번호, 마감, 오류 상태를 저장한다. 로컬 메시지 ID와 시작·자기소개·마무리·종료의 고유 키를 정의한다. 세션에는 자료/프롬프트 버전과 해시도 고정해 재개 때 후보 성격이나 역할 지시가 조용히 바뀌지 않게 한다.

발화와 차례 완료는 같은 `state.json` 원자적 저장으로 확정한다. 문서는 확정 상태의 출력으로 만들고, 상태 저장 직후 종료된 경우 다시 생성할 수 있게 한다. 외부 원문 편집과 단순 출력 지연을 구분할 생성본 해시·상태 버전을 기록한다. 복구는 하네스 명령을 통해서만 수행한다.

면접 시작 인사이트 확인과 실제 저장본을 같은 내용으로 묶고, 피드백 확정·기준 전후 사본을 기존 검증과 연결한다.

완료 기준: 합성 중단 지점별 재실행에서 확정 발화가 중복되지 않는다. 문서 손상·이중 실행·기준 변경을 감지하며 평가 대기 단계를 건너뛰지 않는다. 대응 기준: A02, A05, A08, A10.

### P3. 역할별 모델 실행기

지원자 입력과 면접관 입력을 각각 허용 필드로 구성한다. 전체 세션·전체 후보 자료를 모델에 전달하지 않는다. 같은 후보의 확정 대화만 포함한다. 지원자 응답과 면접관 발화의 별도 길이 제한을 모델 스키마에 반영한다.

현재 `subprocess.run` 중심 실행을 취소 가능한 실행으로 바꾼다. 프로세스 핸들·타임아웃·종료 회수를 관리하고, 출력 형식이 올바른 정상 완료 결과만 반환한다. 호출별 임시 작업 위치와 도구/MCP/훅/프로젝트 설정 제한을 유지한다. 오류 본문에 인증값이나 원시 stderr가 섞이지 않게 한다.

프로세스를 실행하기 전에 요청을 저장한다. 재시도는 동일 논리 차례의 새 시도로 처리하며, 이전 시도의 늦은 결과가 도착해도 채택하지 않는다. 한 면접에서 두 역할을 동시에 호출하지 않는다.

완료 기준: 가짜 CLI 프로세스로 타임아웃·취소·잘못된 JSON·중복 완료·늦은 결과를 검증한다. 역할별 입력에 금지 자료가 없는지 구조적으로 검사한다. 이 결과는 실제 Claude 검증과 분리한다. 대응 기준: A05, A06, A07.

### P4. 터미널 면접 루프

카카오 수신/전송 루프를 제거하고 `사람 입력 → 후보`, `AI 면접관 → 후보` 차례를 연결한다. 시작 선언과 자기소개 요청은 하네스가 기록하고 첫 후보 응답을 한 번만 요청한다.

입력란과 출력 갱신을 분리해 한국어를 입력하는 동안 타이머·답변 출력이 작성 중인 문장을 망가뜨리지 않게 한다. 평문 입력과 스펙의 `/last`, `/end`, `/status`, `/retry`를 제공한다. AI 면접에서는 사람이 입력한 평문을 자동 질문으로 접수하지 않는다.

1,800/1,200초 마감, 120초 마무리 창, 후보 질문에 대한 면접관 답변과 마지막 말 처리를 연결한다. 마무리 경계에서 후보의 진행 중 답과 새 일반 질문을 구분한다. 마감·Ctrl+C 때 실제 모델 프로세스를 정리하고 종료 뒤 발화를 차단한다.

완료 기준: 가짜 모델로 사람 면접 한 건과 AI 면접 한 건을 터미널에서 끝까지 진행할 수 있다. 재개하면 남은 시간이 이어지고 마감 후 재개는 종료부터 처리한다. 시간 만료 검사는 가짜 시계를 사용한다. 대응 기준: A03, A04, A05, A06.

### P5. 후보 프롬프트와 대화 품질

기존 candidate-actor의 사실·기억·현재 상태·되묻기·정정 규칙에 스펙 6절의 추가 문안을 합친다. 말투는 원본 `self_expression`을 우선한다. 넓은 질문에 대한 덜 정리된 답, 후속 질문에서의 구체화, 모르는 내용 인정, 기존 미숙함을 남기는 동작을 보완한다.

모든 후보에게 추상성·머뭇거림·실수·약점을 할당하지 않는다. 자연스러움의 비율 설정이나 무작위 오타 삽입은 만들지 않는다. 유창한 후보는 유창하게 답할 수 있고, 구체적인 질문에는 알고 있는 범위를 구체적으로 답해야 한다.

면접관 프롬프트에서는 반복 요약·과장된 칭찬·평가표 낭독을 줄이고, 필요한 후속 질문과 지원자 질문에 대한 답을 유지한다. 순위 프롬프트에는 표현의 유창함·짧음·망설임을 역량으로 치환하지 않는 원칙을 확인한다.

실제 Claude 검사는 아래 대화 묶음을 쓴다. 후보의 비공개 사실을 검증용으로 참고할 수 있지만, 검사 과정의 원문 설정을 실제 면접관 입력이나 사용자용 보고서에 섞지 않는다.

| 검사 | 관찰할 동작 |
| --- | --- |
| 넓은 질문 → 구체적인 후속 질문 | 처음부터 모든 사실을 나열하지 않아도 되며, 후속 질문에는 실제 경험으로 구체화한다. |
| 정확한 수치가 없는 질문 | 수치를 발명하지 않고 모르는 범위를 밝힌다. |
| 정확한 사실이 있는 질문 | 자연스러움을 핑계로 이미 아는 사실을 무작위로 틀리거나 잊지 않는다. |
| 담당 범위를 과장한 질문 | 본인과 다른 사람의 일을 구분한다. |
| 압박·반박·사실 정정 | 성향은 유지하되 무조건 동의·방어·자기비난으로 흐르지 않는다. |
| 추상적인 이유·선호 | 매번 교훈과 개선 계획까지 완벽하게 정리하지 않아도 된다. |
| 후보의 회사 질문 → 면접관 답변 | 이미 받은 답을 반영하고 같은 질문을 처음부터 되풀이하지 않는다. |
| 여러 차례 대화 | 반복 말버릇, 기계적인 STAR, 답변 길이 획일화, 다른 후보 기억 혼입이 없는지 본다. |

대표 후보 P07·P03·P06으로 연결·표현을 먼저 확인한 뒤, 확정 후보군 8명 모두에 짧은 대화 묶음을 적용한다. 먼저 소규모 검사를 통과하고 프롬프트를 고친 후 전체 후보 검사를 한 번 진행한다. 불합격 사례를 구체적으로 기록하며, 이미 통과한 검사를 이유 없이 계속 반복하지 않는다.

완료 기준: 사실을 보존하면서 질문의 구체성에 따라 답변이 달라지고 후보별 말투가 유지된다. 일정 비율로 `음`을 쓰거나 평균 글자 수가 줄었다는 이유만으로 성공 처리하지 않는다. 합성 예시·형식 테스트 통과와 실제 모델 품질 관찰을 분리한다. 대응 기준: A07, A11.

### P6. 시작 절차와 로컬 완료

`bootstrap.py`, `실행.command`, `실행.bat`, `start-windows.ps1`, `onboarding.py`에서 OS 선택과 서버·카카오 설정을 제거한다. 의존성·인증 검사는 자동으로 수행하며, 실패했을 때만 설치 또는 본인 로그인 절차를 안내한다. 새 명령의 `--config`·`--model` 필수 조건은 제거하고 모델 기본값을 사용한다.

각 면접 시작 전 인사이트 확인, 면접 종료 후 사용자 평가, 변경 여부 확인, 다음 시작을 연결한다. 서버 제출 대신 로컬 순위 저장이 완료 조건이 되도록 `finalize.py`와 상태 전이를 바꾼다. 순위는 최종 기준 해시·원문/평가 해시·실제 인용과 함께 확정하고 재실행 때 재생성하지 않는다.

운영 endpoint, HTTP 인증, 접수, 재시도, 구 제출 schema와 관련 CLI 명령을 제거한다. `httpx` 등 의존성은 실제 사용처가 없어진 것을 확인한 뒤 정리한다. 과거 운영 인증 환경변수가 남아 있어도 모델에 전달되지 않게 기존 차단은 유지한다.

완료 기준: 준비된 환경에서 기준 확인 외 연결 설정 없이 시작하며, 네 번째 사용자 피드백 뒤 로컬 순위로 끝난다. 하네스의 운영 서버 요청이 없는 것을 전송 호출 검사로 확인한다. Claude 자체 네트워크 호출과 혼동하지 않는다. 대응 기준: A01, A08, A09.

### P7. 패키지·문서·회귀 정리

`pyproject.toml`의 패키지 목록과 자료 포함 규칙, `scripts/package.py`의 ZIP 허용 목록에 후보 전용 패키지와 새 프롬프트를 반영한다. 개발 참고 폴더가 없는 별도 설치 위치에서도 실행 자료가 모두 로드되는지 검사한다. `.runtime/`, 인증 파일, 원본 서버 자료, 개발자의 절대 경로는 배포에 포함하지 않는다.

README·setup·첫 실행 안내·예제 설정·doctor 출력·검증 문서를 갱신한다. Computer Use·운영 API 문서는 현재 사용 안내에서 제거하고 과거 방식의 보관 자료임을 표시한다. 실행 문서에 남은 카카오 설정/제출 지시를 검색해 정리한다.

기존 테스트는 유지할 규칙과 제거한 기능으로 구분한다. 후보 배정·시간·평가·인사이트·인용·인증 경계 검사는 보존하거나 새 구조로 옮긴다. 폐지된 기능을 검사하던 테스트는 대체 검증과 제거 사유를 기록한다. 실패를 숨기기 위해 테스트를 삭제하지 않는다.

완료 기준: 독립 설치에서 필수 자료가 읽히고, 시작 안내와 실제 명령이 일치한다. 아래 검증 표의 합성 검사와 실제 연결 결과가 따로 기록된다. 대응 기준: A01~A12.

## 4. 검증 계획

코드 변경 후 실행할 공통 명령은 다음과 같다. 이 문서 작성만으로 아래 검사가 수행됐다고 간주하지 않는다.

```sh
python -m pytest -q
python -m harness doctor
```

| 구분 | 검사 범위 | 판정할 수 없는 것 |
| --- | --- | --- |
| 정적 검사 / doctor | 자료·프롬프트·스키마·패키지·후보군·폐지한 설정의 잔존 여부 | 실제 Claude 로그인·응답 품질 |
| 합성 단위·통합 검사 | 한 번 배정, 차례/중복 방지, 역할 입력, 시간, 저장 중단, 문서 변경, 사용자 대기, 로컬 순위 | 실제 사람의 평가와 자연스러운 대화 |
| 가짜 CLI 프로세스 검사 | 타임아웃·취소·종료 회수·잘못된 출력·늦은 결과 | 실제 Claude 실행 성공 |
| 실제 Claude 짧은 연결 검사 | 본인 로그인, 후보/면접관 호출, 실제 지연, 출력 형식 | 전체 후보와 네 명 실습 품질 |
| 실제 Claude 품질 검사 | P5의 대화 묶음과 사실·말투·기억 일관성 | 사람이 수행한 첫 면접과 실제 사용자 평가 완료 |
| Mac·Windows 터미널 확인 | 설치/실행·한국어 입력·표시·Ctrl+C·프로세스 취소·재개 | 확인하지 않은 다른 OS의 동작 |
| 실제 네 명 실습 | 첫 사람 면접, 이후 AI 면접, 각 사용자 평가, 최종 로컬 결과 | 사용자 입력 없이 자동으로 통과시킬 수 없음 |

합성 네 명 흐름에서는 별도 임시 세션과 명시적인 테스트 더블의 사람 입력을 쓸 수 있다. 이를 실제 사용자 판단으로 저장하거나 행사 실습으로 보고하지 않는다. 실제 네 명 실습에서는 사람 입력 단계에서 멈추고 기다린다.

의미 있는 장애 검사는 다음을 포함한다.

- 생성 시작 직후, 상태 확정 직후, 문서 갱신 직전, 순위 확정 직후의 중단과 재개.
- 같은 차례의 재시도·이전 시도 지연 반환·두 하네스 동시 실행.
- 28/18분 경계와 30/20분 마감에 진행 중인 면접관/지원자 생성.
- 남은 시간이 있는 재개와 이미 마감된 재개. 시스템 시각 후퇴 감지.
- 인사이트 확인 직후 변경, 면접 중 변경, 변경 여부 선택 불일치, 빈 평가.
- 원문 변경·잘림과 단순 문서 갱신 지연의 구분.
- persona/구간/기준/평가를 다른 역할 입력으로 섞으려는 잘못된 객체.
- 설치 패키지에서 후보 자료 하나가 빠진 경우의 시작 차단과 후보군 보존.
- 최종 인용에 면접관 질문·다른 후보 발언·원문에 없는 문장이 포함된 경우 거부.
- 기존 `.runtime/light`와 신규 세션을 같은 폴더로 열려는 경우 보존과 안내.

실제 모델 기록에는 모델·CLI 버전, 검사 날짜, 프롬프트/자료 해시, 시도 수, 오류와 관찰 결과를 남긴다. 아직 확인하지 않은 연결과 OS는 `미검증`으로 기록한다. 인증값과 후보 원문 전체를 일반 검증 보고서에 출력하지 않는다.

## 5. 의존 순서와 완료 보고

```text
P0 기준 정리
  → P1 자료 준비
  → P2 상태/기록
  → P3 모델 실행기
  → P4 터미널 면접
  → P5 프롬프트/실제 대화
  → P6 시작/평가/로컬 완료
  → P7 패키지/문서/회귀
```

각 단계에서는 해당 변경에 필요한 검사를 먼저 실행하고, 코드 작업을 마칠 때 전체 `pytest`와 `doctor`를 실행한다. 이후 새 실패나 변경이 생긴 경우에만 관련 검사를 다시 넓힌다. 실제 사용자 네 명 실습을 진행하지 못했으면 구현·합성 검증 완료와 실제 운영 검증을 분리해 보고한다.

최종 구현 보고에는 변경한 동작, 실제 실행한 명령과 결과, 실제 Claude 검사 범위, Mac/Windows 확인 범위, 남은 미검증 항목을 적는다. 운영 서버와 카카오 연결 검사는 새 구조의 완료 조건에 포함하지 않는다.

## 6. 구현 결과

- 새 동작 테스트의 실패를 먼저 확인한 뒤 상태·차례·터미널·순위 저장을 구현했다.
