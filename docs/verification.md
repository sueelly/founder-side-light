# 터미널 면접 검증 기록

기준일: 2026-09-18. [현재 스펙](terminal-interview-spec.md)의 자동 검사, 실제 모델 호출,
개발용 리허설을 구분한다. 연결 성공과 내용의 사실성, 전체 사용자 실습 완료는 서로 다른 결과다.

## 자동 검사: GitHub 공유용 정리 후

2026-09-18, Mac의 프로젝트 가상환경에서 수행했다.

| 검사 | 결과 |
| --- | --- |
| `python -m pytest -q` | 149개 통과, 11.46초 |
| `python -m harness doctor` | 자료·후보군·프롬프트·설치 상태 정적 검사 통과 |
| wheel 빌드·소스 밖 설치·리소스 로드 | 전체 테스트에 포함, 통과 |
| 별도 새 가상환경에 실행 의존성만 설치 | 소스 복사본 삭제 후 8명 자료·CLI 도움말·doctor 통과. pytest 미설치 확인 |
| Git 소스 아카이브의 세션·인증값·캐시 제외 | 합성 파일 검사 통과 |
| 시작 흐름 | 자동 설치·개발 검사·자동 브라우저 로그인 없이 기준 확인. 완료 결과는 인증 없이 조회 |

폐지된 설치 마법사 검사는 제거하고 새 시작 계약과 표준 패키징 검사를 추가했다.
자료·프롬프트 해시는 아래 기존 값과 동일하다. 이번 정리는 실제 Claude 면접이나
전체 사용자 리허설을 다시 실행한 결과가 아니다. Mac·Windows CI는 저장소 워크플로로 제공한다.

## 이전 자동 검사 기준

Mac, Python 3.14.0의 프로젝트 가상환경에서 수행한 기록이다.

| 검사 | 결과 |
| --- | --- |
| `python -m pytest -q` | 150개 통과, 8.07초 |
| `python -m harness doctor` | 자료·후보군·프롬프트·설치 상태 정적 검사 통과 |
| 별도 가상환경 wheel 설치 후 소스 밖에서 `python -I -m harness doctor` | 독립 설치 자료·모듈 로드 통과 |

위 수치는 레거시 정리 전 검사 기록이다.

새 터미널 계약 테스트 25개의 실패를 먼저 확인한 뒤 구현했다. 재시작 시계 후퇴, 마감 직후
발화 저장, 긴 stdin 전달 중 정지 문제도 재현 검사를 추가해 수정했다.

| 영역 | 자동 검사로 확인한 범위 |
| --- | --- |
| 배정·역할 | P07 선행·고정 순서·8명 자료 완비, 중첩 허용 목록과 역할별 자료 차단 |
| 시간·차례 | 한 번 확정, 대기 중 입력 거부, 마감 후 결과 폐기, 중단·재개·시계 후퇴 |
| 저장 | 단일 실행 잠금, 원자적 확정, 문서 출력 실패 복구, 외부 변경·잘림 감지 |
| 사용자 판단·순위 | 시작 기준 해시, 빈 평가·변경 여부 불일치 차단, 인용 검증, 확정 순위 재사용 |
| 실행기·터미널 | 가짜 CLI의 큰 입력·취소·타임아웃·프로세스 정리, POSIX 입력 파이프의 한국어·붙여넣기·초안 보존 |

합성 네 명 흐름의 평가는 테스트 자료다. 터미널 자동 검사는 실제 한국어 IME 조합이나
네이티브 Windows 화면 검증을 대신하지 않는다. 정리 전 Windows용 배포본을 Mac에서 풀어
검사한 결과도 Windows 실기 성공으로 보지 않는다.

## 짧은 실제 Claude 검사

본인 Claude 로그인, CLI `2.1.69`, 요청 모델 `sonnet`으로 수행했다. 별칭만으로 실제 라우팅된
모델의 세부 버전을 단정하지 않는다. 사용자 세션·평가를 만들지 않은 별도 개발 입력이다.

| 역할 | 결과와 한계 |
| --- | --- |
| 지원자 | 초기 stdin 장애로 3회 시간 초과. 수정 후 8명 × 2회, 총 16회 성공. 첫 답·상대 연도·선호 지시 보완 후 4회 추가 성공. 후보마다 표현 개선 정도가 달랐다. |
| 면접관 | 합성 후보 발언에 대한 후속 질문 1회 성공, 6.728초. |
| 순위 | 짧은 합성 네 후보 입력으로 1회 성공, 56.716초. 근거 없는 시점 해석을 줄이는 지시를 보완한 뒤 1회 추가 성공, 52.323초. |

지원자 검사의 세부 관찰은 [지원자 품질 검증](candidate-quality-verification.md)에 기록했다.
순위 출력의 원문 인용 검사는 출처·문자열의 일치를 확인하며, 설명 전체의 의미적 정확성을
자동 보장하지 않는다. 최초 출력에는 공유 시점이 없는 행동을 조기 공유로 해석한 문제가 있었다.
보완 후 같은 합성 입력에서는 공유 시점을 알 수 없다고 명시했다.

이 단계의 최종 자료·프롬프트 runtime SHA-256:
`da6cae54d251579070bbc394af84c01c3a1f2c3fe504449559dfc27a39ff2c5b`.

확정 후보 8명의 허용된 과거·현재·말투 자료를 가져왔고, 이력 사실 단위 608개는 원문 순서와
내용을 보존했다. 추출 버전은 `persona-import-2`다. 공개 지원서와 후보 설정 사이에 남은 일부
차이는 모델로 임의 보정하지 않았다. 검증용 원문·메타데이터는 로컬에 보관하며 배포하지 않는다.

## 네 명 실연결 리허설

별도 복사본에서 P07 → P01 → P06 → P08의 네 면접과 각 피드백 확정 흐름을 수행했다.
개발자가 첫 면접관과 평가 입력을 담당한 리허설이며 실제 사용자가 네 평가를 끝낸 것으로
보고하지 않는다. 이후 세 면접은 실제 Claude 면접관·지원자가 대화했다.

**최종 순위 생성은 완료하지 못했다.** 네 명의 긴 기록으로 순위를 요청한 두 시도가 각각
120초 제한에서 시간 초과됐다. 앞선 짧은 합성 입력의 순위 생성 성공으로 이 실패를 갈음하지 않는다.

대화에서도 다음 한계를 확인했다.

- 면접관이 마무리를 안내한 뒤 하네스가 후보 질문·마지막 말을 다시 요청하는 중복이 있었다.
- 후보가 후속 질문에 답하면서 원자료에 없는 동료 반응·업무 조정·갈등·실패 사건을 덧붙였다.
- 완료 확인이나 피드백이 기록되지 않았다는 사실을 후속 연락·확인 행동이 없었다는 뜻으로
  바꾸거나, 서로 별개인 사건에 새로운 선후·인과관계를 붙인 답이 있었다.
- 특히 긴 대화에서 반복적인 자기비판과 완결된 자기분석이 강해졌다. 주요 수치가 맞더라도
  주변 사건과 성향까지 정확히 재현된다고 볼 수 없다.

후보 원자료를 대조한 품질 검토는 이미 확정한 평가와 순위 모델 입력에서 분리했다.
별도 복사본의 인간화 v2 프롬프트 실험은 현재 원본에 반영하지 않았다. 해당 실험의 짧은
호출 결과를 원본의 개선 완료나 20분 면접 검증 완료로 포함하지 않는다.

## 남은 확인

- 긴 네 명 기록으로 최종 순위를 안정적으로 생성·저장하는 흐름.
- 마무리 안내 중복과 장시간 대화의 사실·성향 일관성.
- 실제 사용자가 첫 면접·네 평가·최종 결과 확인을 수행하는 전체 실습.
- Mac 네이티브 한국어 IME 조합 중 출력·창 크기 변경, Windows 실기의 입력·취소·재개.

개발 검사는 [구현·검증 계획](terminal-interview-plan.md)에 따라 별도로 실행한다.
`pytest`나 `doctor`를 사용자의 면접 시작마다 자동 실행하지 않는다.
