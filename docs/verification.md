# 터미널 면접 검증 기록

검사일: 2026-09-18. 이 문서는 터미널 버전의 검증만 다룹니다. 이전 카카오 검사는 보관 자료입니다.

## 구현 범위

카카오·운영 서버 모듈과 관련 명령·설정을 제거했습니다. 첫 면접관은 사람, 다음 세 면접관은 Claude이고
지원자는 모두 Claude입니다. 하네스 한 개가 차례와 시간을 관리하며 발화가 완성되면 터미널과 문서에 표시합니다.
기준 확인, 실제 사용자 평가, 인사이트 변경 여부 확인을 거쳐 최종 순위를 로컬에 저장합니다.

## 테스트부터 구현

- 변경 전 기준: 기존 테스트 **98개 통과, 1개 실패**. 실패는 한글 Windows 시작 파일의 유니코드 정규화에 따른 배포 누락이었습니다.
- 새 터미널 계약 테스트 25개를 먼저 작성하고 **25개 실패**를 확인한 뒤 구현했습니다.
- 후보 입력·자료 경계 테스트도 구현 전 실패를 확인하고 개발했습니다.
- 독립 검토에서 재시작 시계 후퇴와 마감 직후 발화 저장을 재현했습니다. 저장 직전 중단까지 포함한 회귀 테스트를 추가하고 수정했습니다.
- 실제 Claude 검사에서 긴 stdin 전달이 멈추는 문제를 발견했습니다. 늦게 입력을 읽는 가짜 CLI로 재현한 뒤 취소 감시와 입력 전달을 분리해 수정했습니다.
- 폐지 기능의 기존 테스트 원본은 보관했습니다. 배정·시간·평가·인용·인증 경계는 새 경로에서 다시 검사하며, 카카오 조작과 서버 제출의 성공을 요구하던 검사는 현재 제품에 적용하지 않습니다.

## 최종 자동 검사

Mac, Python 3.14.0의 프로젝트 `.venv`에서 다음을 실행했습니다.

| 명령 | 결과 |
| --- | --- |
| `python -m pytest -q` | **150개 통과, 8.07초** |
| `python -m harness doctor` | 자료·후보군·프롬프트·설치 상태 정적 검사 통과 |
| `bash -n 실행.command` | Mac 시작 파일 구문 검사 통과 |

wheel을 system-site-packages가 꺼진 별도 가상환경에 설치하고 소스 밖에서
`python -I -m harness doctor`를 실행했습니다. 자료·모듈이 모두 독립 설치 위치에서 로드되는 것을
확인했습니다. Mac/Windows ZIP도 각각 풀어 해당 배포본의 doctor가 통과했습니다.
Windows ZIP의 이 검사는 Mac에서 실행한 것이며 Windows 실기 검증과 구분합니다.
배포에는 로컬 세션·인증 파일·폐지된 실행 모듈과 endpoint를 포함하지 않습니다.

## 자동 검증의 범위

| 영역 | 확인한 동작 |
| --- | --- |
| 배정 | P07 선행, 나머지 세 구간 각 1명, 고정 순서, 8명 자료 완비, 재시작 시 재추첨 없음 |
| 역할 입력 | 중첩 필드까지 허용 목록 검사, 지원자 기준·평가 차단, 면접관·순위 모델에 후보 전용 설정 차단 |
| 시간과 차례 | 사람/AI 교대, 한 번 확정, 대기 중 입력 거부, 마무리, 마감 후 발화 폐기, 재시작·시계 후퇴 |
| 기록 | 단일 실행 잠금, 상태와 발화 원자적 확정, 문서 출력 실패 복구, 외부 편집·잘림 감지 |
| 사용자 판단 | 시작 기준 해시 확인, 빈 평가 차단, 변경 여부 불일치 차단, 네 번째 평가 이후 순위 생성 |
| 순위 | 실제 원문 인용, 해당 후보 근거만 허용, 최종 기준 해시, 재실행 시 확정 결과 재사용 |
| 모델 실행 | 가짜 실제 프로세스로 큰 입력, 취소, 타임아웃, 잘못된 JSON, 자식 프로세스 정리 |
| 터미널 | 실제 prompt_toolkit과 POSIX 입력 파이프로 한국어 문자열·붙여넣기·초안 보존·마감·Ctrl+C |

터미널 검사는 Mac의 입력 스택을 사용하는 합성 검사입니다. 운영체제의 실제 한국어 IME 조합이나
네이티브 Windows 화면을 확인한 결과는 아닙니다. 합성 네 명 흐름에서 사용하는 평가도 테스트 자료입니다.

## 후보 자료와 실제 모델

확정 후보군 8명에 대해 허용된 과거·현재·말투 자료만 가져왔습니다. 이력의 사실 단위 608개는
원문 순서와 내용을 보존했고 내부 참조·평가 메타데이터는 제거했습니다. 추출 버전은 `persona-import-2`입니다.
원본의 공개 지원서와 후보 설정 사이에 남아 있는 일부 차이는 모델로 임의 보정하지 않았습니다.

본인 Claude 로그인 확인은 성공했습니다. CLI 2.1.69, 요청 모델 `sonnet`으로 검사했습니다.
요청 별칭만으로 실제 라우팅된 모델 버전을 단정하지 않습니다.

- 지원자: 초기 stdin 장애로 3회 시간 초과. 수정 후 8명 × 2회 **16회 성공**.
  첫 답의 과도한 완결성·상대 연도·선호 유지 지시를 보완한 뒤 **4회 추가 성공**.
  짧은 답과 연도 정정이 관찰됐지만 후보마다 표현 개선 정도는 다릅니다.
  구체적 관찰과 한계는 [지원자 품질 검증](candidate-quality-verification.md)에 기록합니다.
- 면접관: 합성 후보 발언에 실제 후속 질문 **1회 성공**, 6.728초.
- 순위: 합성 네 후보 자료에서 실제 생성 **1회 성공**, 56.716초. 네 후보·순위 중복과
  해당 후보 원문 인용 검사를 통과했습니다. 다만 시점이 없는 행동을 조기 공유로 해석한 사례가 있어
  기록에 없는 시점·담당 범위·완료 여부를 확정하지 않는 지시를 보완했습니다.
  같은 합성 입력의 보완 후 검사 **1회도 성공**, 52.323초. 이번 출력은 공유 시점을 알 수 없다고 명시했습니다.

최종 자료·프롬프트 런타임 SHA-256은
`da6cae54d251579070bbc394af84c01c3a1f2c3fe504449559dfc27a39ff2c5b`입니다.

면접관·순위 검사도 실제 사용자 세션을 만들지 않은 합성 개발 입력입니다. 원문 인용 검사는
출처와 문자열의 일치를 확인하며 설명 전체의 의미적 정확성을 자동 보장하지 않습니다.
실제 모델 검증 기록은 별도 `.runtime/verification/`에 보관하고 배포에 넣지 않습니다.

## 남은 실제 환경 확인

- 실제 사용자가 첫 면접과 네 번의 평가를 수행하는 전체 실습.
- Mac 네이티브 한국어 IME 조합 중 출력·창 크기 변경.
- Windows 실기에서 시작 파일·한국어 입력·프로세스 취소·재개.
- 장시간 대화에서의 후보별 사실·기억·표현 일관성. 짧은 실제 모델 검사를 전체 품질 보장으로 보지 않습니다.

카카오 연결과 운영 서버 접수는 폐지된 기능이므로 새 버전의 검사 대상이 아닙니다.
