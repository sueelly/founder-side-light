# 터미널 면접 스펙

기준일: 2026-09-18. 현재 실행 계약을 정리한다. 사용법은 [README](../README.md),
개발 절차는 [구현·검증 계획](terminal-interview-plan.md), 결과와 한계는 [검증 기록](verification.md)을 따른다.

## 실행과 사용자 흐름

Python 환경과 본인 계정으로 로그인한 Claude CLI를 준비한 뒤 설치·실행한다.

```sh
python -m pip install -c requirements.lock.txt .
python -m harness start
```

준비된 환경에서는 세션의 `insights.md` 작성·확인부터 시작한다. 자동 설치나 OS별 시작 파일은
제공하지 않으며, `pytest`와 `doctor`는 개발자가 필요할 때 실행한다. 모델 실행에 필요한
Claude 설치·인증 확인은 유지한다. 카카오와 운영 서버는 사용하지 않는다.

```text
기준 확인 → 사람 면접 → 사용자 평가·인사이트 변경 여부
         → AI 면접   → 사용자 평가·인사이트 변경 여부 (3회)
         → 최종 기준으로 네 명 순위 생성 → 로컬 저장
```

- 회사·직무는 코어브릿지웍스 / 경영지원·사업운영 담당자이며 모두 기술면접을 통과한 인성면접 대상이다.
- 총 네 명이다. 첫 면접관은 실제 사용자, 다음 세 면접관과 모든 지원자는 Claude다.
- 첫 초기화에서 [확정 후보군](../harness/candidate_pools.json)으로 P07을 먼저 배정한다.
  나머지 세 구간에서 각각 한 명을 뽑고 뒤 세 순서를 섞는다. 재시작 때 다시 추첨하거나 모델로 재분류하지 않는다.
- 각 면접 전에 기준 내용을 보여주고 실제 사용자의 `시작` 입력을 기다린다. 빈 기준이나 템플릿
  상태로는 시작하지 않는다. 확인 후 내용이 바뀌면 다시 확인한다.
- 첫 발화는 `OOO님 면접 시작하겠습니다`, 마지막 발화는 `수고하셨습니다`다.

## 대화와 시간

한 하네스가 차례·시간·확정 기록을 관리한다. 모델은 자기 차례에 발화 하나만 생성한다.
완성된 발화를 터미널과 문서에 표시하며, 생성 중에는 역할과 남은 시간을 보여준다.
문서를 감시하는 상주 에이전트나 글자 단위 스트리밍은 사용하지 않는다.

| 입력 | 동작 |
| --- | --- |
| 일반 텍스트 / `q 질문` | 첫 면접에서 사용자의 발화 입력 |
| `/last` | 사람 면접 마무리 요청 |
| `/end` | 마무리 안내에 대한 후보 답을 받은 뒤 종료 |
| `/status` | 현재 상태와 남은 시간 확인 |
| `/retry` | 실패·중단된 현재 모델 차례 재시도 |
| Ctrl+C | 활성 모델 프로세스를 정리하고 중단 |

지원자 응답 대기 중 새 질문을 자동 접수하지 않는다. 작성 중인 입력은 가능한 한 보존한다.
다음 세 AI 면접에는 사람이 대신 질문을 입력하지 않는다. 후보가 회사에 질문하면 면접관이
알고 있는 범위에서 답하며, 모르는 회사 정책은 만들지 않는다.

사람 면접은 최대 1,800초, AI 면접은 각 1,200초다. 시작 시각과 마감을 한 번 저장하고 생성·오류
대기·중단 시간을 포함한다. 재시작으로 시간을 늘리지 않는다. 실행 중에는 단조 시계를 사용하며,
재개 시 저장된 절대 마감과 시계 후퇴 여부를 확인한다.

처음 1~2분은 자기소개·기본 사항, 마지막 2분은 후보 질문·마지막 말에 사용한다. 마무리 시점에는
새 본 질문을 시작하지 않고, 이미 생성 중인 후보 답은 실제 마감 안에서 처리한다. 마감에 도달하면
활성 생성을 취소하고 종료를 한 번 기록한다. 마감 전에 상태에 확정되지 않은 응답과 종료 뒤 발화는
원문에 넣지 않는다. 중단 중 마감이 지났다면 재개 시 종료부터 처리하고 지연 사실을 기록한다.

## 역할별 입력과 후보 표현

| 역할 | 받는 자료 |
| --- | --- |
| 지원자 | 본인의 과거·현재·말투, 공개 지원서·회사 자료, 현재 면접 상황과 해당 면접의 확정 대화 |
| 면접관 | 공개 회사·해당 후보 지원 자료, 시작 때 기준 사본, 해당 면접 대화·단계·남은 시간 |
| 순위 | 최종 기준, 공개 회사 자료, 네 명의 확정 원문·사용자 평가·당시 기준·시간·진행 예외 |

지원자에게 인사이트·평가·순위·다른 후보를 주지 않는다. 면접관과 순위 모델에 후보 전용 설정을
주지 않는다. 구간·미래 시나리오·미래 근속 수치·평가 정답은 어느 모델에도 제공하지 않는다.
허용 필드로 입력을 새로 구성하고 중첩 필드까지 검사한다. 모델은 파일·화면·검색·MCP 도구 없이
실행되며, 세션 객체 전체를 읽지 않는다.

확정 후보군 P01·P02·P03·P04·P06·P07·P08·P10의 후보 전용 자료를 패키지에 포함한다.
허용된 과거·현재 사실과 현재 생각의 확실성을 보존하며, 원본 서버나 개발자 폴더에 의존하지 않는다.
후보 설정 원문은 면접 화면·평가·최종 순위 문서에 출력하지 않는다. 이 분리는 모델 입력의 경계이며
로컬 파일을 사용자에게 숨기는 보안 기능은 아니다.

표현의 우선순위는 사실·기억 범위, 후보의 성향·말투, 대화 맥락, 자연스러움 순이다. 넓은 질문에는
요점부터 답하고 구체적인 질문에는 실제 행동·범위·시점을 설명한다. 모든 답을 성과·교훈으로 끝내거나
사람처럼 보이려고 새 약점·사건·수치·오타·말더듬을 만들지 않는다. 기존 한계와 선호는 유지하며
잘못된 전제는 후보의 성향에 맞게 바로잡는다.

발화 결과는 `{"text":"이번 발화"}`다. 지원자는 최대 1,800자, 면접관은 최대 1,500자이며 화자·ID·시각은
하네스가 붙인다. 형식 검사는 사실성과 자연스러움을 보장하지 않는다. 현재 알려진 표현 한계와
별도 실험 여부는 [검증 기록](verification.md)에 구분한다.

## 기준·평가·순위

`insights.md`가 기준 원본이다. 사용자 직접 편집이나 구체적으로 요청한 수정만 반영하며 대화에서
기준을 자동 추출·학습하지 않는다. 진행 중인 면접에는 시작 때 확정한 기준 사본을 쓴다.

매 면접 후 실제 사용자가 `feedback.md`의 종합 평가·근거·우려·확인할 점을 작성하고 인사이트 변경
여부를 선택한다. 빈 평가와 실제 변경에 맞지 않는 선택은 확정하지 않는다. 평가와 기준 사본이
확정돼야 다음 후보를 시작할 수 있다. 하네스나 모델이 사용자의 판단을 만들어 대신 입력하지 않는다.

네 번째 평가 후 최종 기준으로 순위를 생성한다. 실제 후보 발언과 확정 사용자 평가의 인용을
검사하고 근거·불확실성과 함께 `ranking.md`, `ranking.json`에 저장한다. 외부 제출은 없다.
생성 실패를 완료로 처리하지 않으며, 확정된 결과는 재실행해도 모델을 다시 호출하지 않는다.

## 저장·중단·복구

기본 세션 경로는 `.runtime/terminal-light`, 스키마는 `founder-terminal-1`이다.

| 파일 | 내용 |
| --- | --- |
| `state.json` | 배정·시계·차례·확정 발화·평가의 원본. 하네스 명령으로만 변경 |
| `insights.md` | 사용자가 편집하는 기준 |
| 각 후보 `transcript.md` | 확정 대화에서 생성한 면접 원문 |
| `feedback.md` / `feedback.confirmed.md` | 사용자 평가 입력 / 확정 사본 |
| `insights.before.md` / `insights.after.md` | 면접 시작 / 평가 확정 시 기준 사본 |
| `ranking.md` / `ranking.json` | 확정된 로컬 순위 |

세션 잠금으로 중복 실행을 막는다. 요청을 저장한 뒤 모델을 실행하고, 유효한 차례의 발화와 차례 완료를
한 번의 원자적 상태 저장으로 확정한다. 재시도·취소 뒤 늦게 온 결과는 채택하지 않는다. 모델이 여러 번
실행될 수 있어도 같은 차례의 확정 발화는 한 번만 저장한다.

상태 확정 뒤 문서 출력이 중단되면 저장된 결과로 복구한다. 원문·확정 평가·기준 사본·순위의 외부 변경이나
손상은 자동 덮어쓰지 않는다. 명시적인 `restore-records --confirmed-restore` 선택으로만 확정 상태에서
복원한다. 자료·프롬프트 해시는 세션에 고정하며 변경된 자료로 기존 세션을 조용히 재개하지 않는다.
구 세션을 자동 변환하거나 JSON 직접 편집으로 진행하지 않는다.
